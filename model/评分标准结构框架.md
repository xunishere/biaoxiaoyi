# 采购文件评分标准数据结构

## 一、采购文件数据结构

当前阶段只做采购文件评分标准的数据提取，不在采购侧人为解释主观评价词，也不预先定义“完整、详尽、合理”等词对应的投标文本结构。

采购文件提取的目标是：把“综合评分法”评分表中显式存在的结构、分值、规则和原文保存下来，为后续投标文件关联和模型学习提供基础数据。

推荐数据结构如下：

```json
{
  "project_info": {
    "project_name": "项目名称",
    "project_number": "项目编号",
    "purchaser": "采购单位",
    "procurement_method": "采购方式",
    "budget": "预算金额"
  },
  "scoring_standard": {
    "method": "综合评分法",
    "total_score": 100,
    "score_items": [
      {
        "item_id": "SI-001",
        "item_name": "评分大项名称",
        "score_range": {
          "min": 0,
          "max": 12
        },
        "score_type": "subjective",
        "raw_text": "该评分大项在采购文件中的原文",
        "score_units": [
          {
            "unit_id": "SU-001-01",
            "unit_name": "评分单元名称",
            "score_range": {
              "min": 0,
              "max": 3
            },
            "score_type": "subjective",
            "rule_type": "quality_judgement",
            "dimensions": [
              {
                "dimension_id": "SD-001-01-01",
                "dimension_name": "评分小项或检查点",
                "raw_text": "采购文件中对该检查点的原文描述"
              }
            ],
            "score_levels": [
              {
                "level_id": "SL-001-01-01",
                "score_range": {
                  "min": 3,
                  "max": 3
                },
                "criteria_text": "该档位在采购文件中的原文判定标准"
              },
              {
                "level_id": "SL-001-01-02",
                "score_range": {
                  "min": 1,
                  "max": 2
                },
                "criteria_text": "该档位在采购文件中的原文判定标准"
              },
              {
                "level_id": "SL-001-01-03",
                "score_range": {
                  "min": 0,
                  "max": 0
                },
                "criteria_text": "无相关内容或不得分的原文判定标准"
              }
            ],
            "objective_rule": null,
            "raw_text": "该评分单元在采购文件中的完整原文"
          }
        ]
      }
    ]
  }
}
```

### 1. project_info

保存项目基础信息。

| 字段 | 含义 |
|------|------|
| project_name | 项目名称 |
| project_number | 项目编号 |
| purchaser | 采购单位 |
| procurement_method | 采购方式 |
| budget | 预算金额 |

### 2. scoring_standard

保存评分方法整体信息。

| 字段 | 含义 |
|------|------|
| method | 评分方法，如综合评分法 |
| total_score | 总分 |
| score_items | 评分大项列表 |

### 3. score_item

评分大项，对应综合评分表中的一级评分项目。

| 字段 | 含义 |
|------|------|
| item_id | 评分大项ID |
| item_name | 评分大项名称 |
| score_range | 大项总分区间，通常是0到该项满分 |
| score_type | 客观评分、主观评分或混合评分 |
| raw_text | 评分大项原文 |
| score_units | 该大项下真正产生分值的评分单元 |

### 4. score_unit

评分单元是真正产生分数的对象。每个评分单元都有自己的分值区间，通常是 `0~N`。

| 字段 | 含义 |
|------|------|
| unit_id | 评分单元ID |
| unit_name | 评分单元名称 |
| score_range | 评分单元的分值区间 |
| score_type | objective / subjective / mixed |
| rule_type | 规则类型，如 formula、evidence_count、quality_judgement |
| dimensions | 该评分单元下显式列出的评分小项或检查点 |
| score_levels | 原文中的得分档位 |
| objective_rule | 客观评分的计算或核验规则；主观评分为空 |
| raw_text | 评分单元完整原文 |

### 5. dimensions

dimensions 只保存采购文件中显式写出的评分小项、检查点或内容要求。

它不负责解释这些检查点如何映射到投标文本结构，只负责保留原文结构。

| 字段 | 含义 |
|------|------|
| dimension_id | 检查点ID |
| dimension_name | 检查点名称 |
| raw_text | 采购文件原文 |

### 6. score_levels

score_levels 保存采购文件中显式出现的得分档位。

| 字段 | 含义 |
|------|------|
| level_id | 档位ID |
| score_range | 该档位对应的分数或分数范围 |
| criteria_text | 该档位的原文判定标准 |

例如原文出现：

```text
方案完整详尽，得3分；
方案能够满足基本需要，得2分；
方案不完整，得1分；
无相关方案，不得分。
```

就只抽取为：

| score_range | criteria_text |
|-------------|---------------|
| 3~3 | 方案完整详尽，得3分 |
| 2~2 | 方案能够满足基本需要，得2分 |
| 1~1 | 方案不完整，得1分 |
| 0~0 | 无相关方案，不得分 |

不在此阶段解释“完整详尽”具体应该对应什么投标文本结构。

### 7. objective_rule

objective_rule 只用于客观评分。

例如报价公式、每份合同得几分、证书数量要求、团队人数要求等。

```json
{
  "calculation_type": "count_with_cap",
  "unit_score": 1,
  "max_score": 8,
  "evidence_type": "contract",
  "conditions": [
    "服务期限包含2023年1月1日以后",
    "提供合同扫描件",
    "合同主要内容包括项目名称、盖章页、签订日期"
  ],
  "raw_rule_text": "每份1分，满分8分"
}
```

主观评分没有 objective_rule，只保留 dimensions、score_levels 和 raw_text。

## 二、解释

### 1. 为什么要区分客观评分和主观评分

客观评分和主观评分的后续处理方式不同。

客观评分看的是证据和规则：

```text
投标文件中是否有对应证据
证据是否满足采购文件条件
满足几个条件或几份材料
按公式或数量规则计算得分
```

主观评分看的是原文档位和投标内容匹配情况：

```text
采购文件给出评分单元、检查点和得分档位
投标文件提供对应章节或段落
后续模型根据投标内容与采购原文档位的匹配情况判断分数
```

因此，采购文件提取阶段只需要保存：

1. 评分项结构；
2. 分值区间；
3. 明确列出的评分小项或检查点；
4. 原文得分档位；
5. 客观评分的显式计算规则或证据要求。

不应该在采购文件提取阶段人为定义主观评价词对应的投标文本结构。

### 2. 评分单元和检查点的关系

评分单元是最终产生分数的对象。

检查点是评分单元下面的内容要求，用于后续判断投标响应是否充分。

有两种常见情况。

第一种：每个小项单独给分。

例如：

```text
需求理解 0~12分
1、应用环境、体系结构需求和实施要求理解程度（3分）
2、系统功能需求、性能要求理解程度（3分）
3、合理化建议、风险分析及控制方案（3分）
4、重点、难点问题分析与措施（3分）
```

这里可以拆成4个评分单元，每个评分单元都是 `0~3`。

第二种：多个检查点共同决定一个评分单元的得分。

例如：

```text
培训方案 0~3分
需包含培训计划、培训期限、培训人员、培训内容等，
且需针对不同人员制定不同培训方案。
```

这里“培训方案”整体是一个 `0~3` 的评分单元；培训计划、培训期限、培训人员、培训内容等只是检查点，不单独给分。

### 3. 主观评分词不在采购提取阶段解释

采购文件里出现的“完整详尽”“科学合理”“可行性强”“针对性强”等词，只作为评分档位原文保存。

这些词后续如何对应投标文件文本结构，应该由关联模型或训练样本学习，而不是在采购文件数据结构里手工规定。

因此，本阶段只做：

```text
保存原文评分规则
保存评分层级
保存分值区间
保存客观核验条件
```

不做：

```text
人工解释主观词
人工规定投标文件应该长什么样
人工替模型定义质量判断逻辑
```

### 4. 后续与投标文件关联

后续关联时，以 score_unit 为目标：

```text
采购评分单元 -> 投标文件响应章节/段落/证明材料
```

对于客观评分，关联目标主要是证据材料。

对于主观评分，关联目标主要是方案章节或文本段落。

但主观评分的质量判断不在采购文件提取阶段完成，而是在后续“采购评分标准-投标响应内容”的关联与训练阶段完成。
